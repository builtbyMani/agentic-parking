<decisions>
## Implementation Decisions

### Currency & Mathematical Representation
- **D-01:** Strictly integer paise (1 INR = 100 paise; e.g. ₹38/hr is 3800). Floating point representation is strictly prohibited across backend, database, and LLM communication.
- **D-02:** FX conversion rate to USD is fixed via environment variable `USD_TO_INR_PAISE=8400` ($1.00 USD = 84.00 INR = 8400 paise).

### Schema Architecture
- **D-03:** Separate `AgentMoveLLM` (untrusted LLM output) from `ValidatedMove` (trusted backend object).
- **D-04:** Gemini token generation is constrained via `response_schema=AgentMoveLLM` with fields: `action`, `price_per_hour_paise`, `message`, `reasoning`.
- **D-05:** Metadata fields (`negotiation_id`, `round_num`, `from_agent`, `to_agent`, `latency_ms`, `guard_triggered`, `guard_reason`) are deterministically assigned by Python, never generated by the LLM.

### PolicyGuard & Prose Sanitization
- **D-06:** Lot Floor Clamp: Clamps lot proposed price to `[effective_floor_paise, base_list_paise]`. If driver already offered higher than effective floor, lot cannot offer less than driver's last bid.
- **D-07:** Driver Budget Clamp: Clamps driver proposed price to `[last_driver_bid_paise, min(driver_budget_paise, last_lot_offer_paise)]`. Driver cannot lower previous bid or bid higher than the lot's ask.
- **D-08:** Prepay Discounting: `compute_effective_lot_floor_paise` applies `max_prepay_discount_pct` only when `prepay == True` and `hours >= min_prepay_hours`, rounded to the nearest 100 paise (₹1).
- **D-09:** Regex Prose Sanitizer: Whenever a price is clamped, regex `(?:₹|Rs\.?\s*)\d+(?:\.\d+)?` replaces any rupee string inside `message` with the clamped rupee integer and appends `[Adjusted to policy limit ₹{rupees}/hr]`.

### Database Schema (SQLite)
- **D-10:** `lots` table: `lot_id`, `name`, `distance_m`, `total_slots`, `occupied_slots`, `event_active`, `base_list_paise`, `base_floor_paise`, `max_prepay_discount_pct`.
- **D-11:** `slots` table: `slot_id`, `lot_id`, `sensor_occupied`, `booking_status` (IDLE, SOFT_LOCK, CONFIRMED), `soft_lock_until`.
- **D-12:** `bookings` table: `booking_id`, `negotiation_id`, `lot_id`, `slot_id`, `plate_number`, `hours`, `agreed_rate_paise`, `total_paise`, `usd_cents`, `status`, `paypal_order_id`, `qr_token`, `created_at`.

### Adversarial Fuzz Invariant Verification
- **D-13:** Build an adversarial chaos test running 50 full multi-round negotiations with random illegal prices (-1000, 1500, 9900 paise, bids above budget, offers below floor, text mismatch).
- **D-14:** Prove that 100% of runs uphold all safety invariants without crashing.

</decisions>
