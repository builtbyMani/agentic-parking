  <name>Task 1: Implement serial bridge and virtual hardware twin in backend/serial_bridge.py</name>
  <files>backend/serial_bridge.py</files>
  <read_first>backend/config.py, backend/db.py</read_first>
  <action>
    Create `backend/serial_bridge.py`:
    1. `class SerialBridge`:
       - `port: Optional[str] = ESP32_SERIAL_PORT`
       - `baudrate: int = 115200`
       - `is_connected: bool = False`
       - `gate_state: str = "CLOSED"` # CLOSED | OPEN
       - `event_callback: Optional[Callable] = None`
       - `async def start()`:
         Attempts `serial.Serial(port, baudrate, timeout=1.0)`.
         If successful, spawns background reader thread/task reading lines.
         If fails or port empty: logs `[Virtual Twin] Serial port not connected. Operating in virtual twin mode.`
       - `async def trigger_gate_open(duration_sec: float = 5.0) -> dict`:
         If `is_connected`: sends `GATE:OPEN\n` to serial.
         In both physical and virtual twin mode: sets `gate_state = "OPEN"`, emits event `GATE_OPENED`, sleeps `duration_sec`, sets `gate_state = "CLOSED"`, emits event `GATE_CLOSED`.
       - `async def handle_serial_line(line: str)`:
         Parses `SLOT:A-01:OCCUPIED` -> updates DB slot sensor status, emits `SLOT_SENSOR_CHANGED`.
         Parses `SLOT:A-01:VACANT` -> updates DB slot sensor status, emits `SLOT_SENSOR_CHANGED`.
         Parses `GATE:CLOSED` -> sets `gate_state = "CLOSED"`.
       - `async def simulate_slot_toggle(slot_id: str, occupied: bool)`:
         Helper for manual/demo toggle of slot sensors when hardware is not plugged in.
    2. Singleton `bridge = SerialBridge()`.
  </action>
  <verify>python3 -c "import asyncio; from backend.serial_bridge import bridge; assert bridge.gate_state == 'CLOSED'; res = asyncio.run(bridge.trigger_gate_open(0.1)); assert bridge.gate_state == 'CLOSED'; print('Serial bridge / virtual twin verified')"</verify>
  <acceptance_criteria>
    - SerialBridge cleanly operates in virtual twin mode when no USB hardware is connected
    - trigger_gate_open transitions state to OPEN and auto-closes after duration
    - Sensor events update SQLite and trigger callbacks
  </acceptance_criteria>
  <done>Serial bridge and virtual twin operational in backend/serial_bridge.py.</done>
</task>

    Create `backend/vision_gate.py`:
    1. `class VisionGateScanner`:
       - `detector = cv2.QRCodeDetector()`
       - `last_trigger_time: float = 0`
       - `cooldown_sec: float = 5.0`
       - `def decode_frame(frame: np.ndarray) -> tuple[bool, str]`:
         Uses `detector.detectAndDecode(frame)`. Returns `(True, decoded_text)` if text found, else `(False, "")`.
       - `async def verify_and_actuate(qr_text: str) -> dict`:
         Checks cooldown.
         Calls `verify_signed_qr_token(qr_text)`.
         If valid: triggers `bridge.trigger_gate_open(5.0)`. Returns `{"status": "ACCESS_GRANTED", "booking": data}`.
         If invalid: returns `{"status": "ACCESS_DENIED", "reason": error}`.
       - `async def process_image_file(image_path: str) -> dict`:
         Loads image with `cv2.imread()`, decodes QR, and calls `verify_and_actuate()`.
       - `async def scan_base64_frame(b64_img: str) -> dict`:
         Decodes base64 JPEG/PNG from web clients, decodes QR, and evaluates entry.
    2. Singleton `vision_scanner = VisionGateScanner()`.
  </action>
  <verify>python3 -c "from backend.vision_gate import vision_scanner; assert vision_scanner.cooldown_sec == 5.0; print('Vision scanner verified')"</verify>
  <acceptance_criteria>

    - Integrates verify_signed_qr_token and trigger_gate_open
    - Supports cooldown to avoid multiple simultaneous gate actuations
  </acceptance_criteria>
